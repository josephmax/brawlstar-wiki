# 这 56 题对 BP skill 的启示

2026-09-18。19 条视频，56 道题（53 选人、3 禁用），全部已有逐题机制拆解。按当前校准结果，55 题可用于普通开发试跑，第 2 题单列为双选复核；全部尚未升级为正式 gold。**没有运行模型基线，因此以下是可检验的改进方向，不是已经实现的质量提升。**

## 最有价值的信号：专家在完成阵容任务

这些题不是 56 条独立的“X 克 Y”。有价值的是作者如何在特定地图、选人位次和队友配置下，把某种能力变成下一步可执行的任务。知识库支持其中大量机制解释，也揭示了作者短视频省略的资源、构筑和版本前提。

| 决策能力 | 代表题 | 应观察的行为 | 易误判之处 |
|---|---|---|---|
| 确认阵容缺什么 | 1、10、11、53、56 | 先识别携宝、长线、守卫、进攻或进圈职责，再选候选 | 第三个相似输出可能提高纸面伤害，却无法完成目标 |
| 队友使候选兑现 | 6、8、29、46、50 | 解释谁提供接近、保护、控制、持续作战条件 | 两个支援未必重复；Max + Jae-yong 可改变 Pierce 的作战条件 |
| 地形有前后两种状态 | 2、9、40、44、55 | 比较完整墙与拆墙后的双方获益 | Ruffs 的开墙可能同时摧毁己方 Shade 的路线 |
| 进场终点与技能资源 | 15、37、41、47、56 | 检查到达后会遇到什么控制、如何退出、谁跟进 | 能跳、能穿墙不等于落点安全，更不等于已经充好 Super |
| 把线权变成模式分数 | 7、18、33—35、39、50 | 解释如何携宝、进球、站圈或访问金库 | 抢劫的攻击能力必须计入到达时间；热区外围消耗不能代替踩圈 |
| 第五手预见第六手 | 2、6、8、32、40、44、47、52 | 比较对手仍可低成本补出的反制 | 对当前两人占优，并不表示完整 draft 成立 |
| 首选与 ban 的方向性 | 4、12、21—25、27、39、48、54 | 保留后续发展路线，区别首选方与末选方的 ban 目标 | 首选安全不能变成永不选主动进攻；名单也不是永久 tier 表 |
| 资源体与弹药经济 | 3、14、38、49 | 解释召唤物如何收费、谁清场、展开前如何生存 | 召唤物数量不等于质量；资源体不能替真人拿宝石或踢球 |

标签统计见索引。每题可多标签，次数不能解释为独立样本数量或能力的重要性权重。

## 应当条件化的专家口述

1. **5 题 Poco “火焰完全没用／free win”**：可提取持续治疗与解控窗口考点，但不能写成永久无敌。覆盖范围、冷却、受到的爆发、解控持续时间和构筑都影响结论。
2. **18、33、51 题抢劫 Crow**：当前库偏向线权、反回复和辅助目标压力；历史作者接受他，不足以证明当前金库竞速输出最优。
3. **34 题 Chuck**：当前充能/补充模型不能直接套旧版自动循环假设。布站、启动和终点防守成本必须显式存在。
4. **44 题“对手不能投掷”**：Colette 对墙后的可达性取决于地形、入口和构筑；不能把一句口述固化成全局禁止。
5. **4 题 Colette 抢蓝星**：开局资源必须核实，不能假设已经有 Super。作者列出的首选理由不等于所有抢星路径均已验证。
6. **2 题 Wendy**：护盾、区域工具和跳跃等具体机制必须区分；不能从视频口述的 “heals” 把她简化成通用治疗包。

这类题应奖励识别条件和提出可验证异议。强迫模型合理化任何专家名单，会训练出“答案正确、机制虚构”的系统。

## 与现有 skill 的差距，应先测再改

已阅读的 [BP skill](../../../skills/brawl-stars-bp-slot-decision/SKILL.md) 已要求能力窗口、模式职责、条件化对位、构筑/资源、主动威胁、双选协同与剩余回应。许多考点已有规则覆盖，不能仅凭这批题就判断“缺一条 prompt”。

| 优先级 | 工作 | 何时才修改 skill / 知识 | 验收 |
|---|---|---|---|
| P0 | 局面与名字质量闸门、干净输入、固定知识快照 | 字段未确认就隔离，不让模型猜标签 | 本次产出已完成；待核源继续列明 |
| P1 | 在 55 道普通开发题上记录现 skill 的输出与检索轨迹 | 尚未运行；先识别真实错误分布 | 区分召回漏项、读到不应用、知识缺失、标签版本不适用 |
| P2 | 针对最大错误类别做单项改动 | 召回问题改查询/覆盖；推理问题改决策约束；源缺失补证据 | 成组回归，报告修复与退化；不复制作者答案到 runtime |
| P3 | 专家审订分歧与 56 个反事实追问 | 推导题经审核后才有新的专家标签 | 同一机制换英雄/地图仍有效，不能只背熟题 |
| P4 | 建立新增未见题的封存测试集 | 新视频或专家独立设计局面 | 固定版本，盲审机制与选择，才报告泛化质量 |

当前还发现 Nori 页面部分旧文本残留 tier / strength 风格表述，而库规则已移除此类决策依据。这是可另行修复的文档一致性问题；本次未修改知识库或 BP skill。

## “接近帕累托前沿”的可执行定义

在固定局面、构筑、补丁假设和有限候选集合中，比较候选在**模式职责、对手压力、队友兑现、被反制风险、资源/操作成本**上的证据；只有各维度均不差且至少一维明确更好，才能称为支配。证据未知时标记不可比，不把未知填成零，也不把相互关联的理由条数累加成收益。

这可测得“当前比较集合内的非劣解选择率”。它不证明覆盖所有候选，不证明真实胜率最优，更不能证明全局游戏 Pareto 前沿。另有一条工程前沿：在真实测得的决策质量、token、延迟之间做取舍；两种前沿分开报告。具体记录方式见测评协议。
