# 评分与 Pareto 比较协议 v1

## 标签有四层

1. **局面事实**：地图、模式、已选、位次、ban、构筑，须有原始时间点。当前仅部分字段经过头像/布局检查，全部缺确切补丁，严格 gold 数为 0。
2. **历史专家答案**：作者接受的集合、偏好、条件答案、实际玩家选择分开保存。作者没有列出 ≠ 明确否定；选中实际玩家选择 ≠ 命中参考解。
3. **机制分析**：本次依据当前知识库写出的考点、评分检查与反事实。明确为分析推断，不冒充作者说过，也不自动变成专家 gold。
4. **当前版本专家审题**：审核当前地图/补丁/构筑、候选可行性、其他合理解后，才能用于当前决策质量的强结论。本次尚未完成。

## 数据使用

- 开发输入：`../inputs.calibrated-dev.jsonl`，39 题。仅向被测模型发送 `prompt`；`id` 留在调度侧。结构化调用可用 `input`，禁止混入 reference、analysis、calibration 或来源链接。
- 评分材料：`../cases.calibrated.jsonl`、本目录全部内容、原视频与字幕。须放在被测模型无权检索的环境；仅要求“不要看”不是隔离。
- 原字幕和 `archive/cases.caption-v1.jsonl` 保留，用于审计。旧的 37 题输入仅为采集历史，已被本版替代。
- 位次 4/5 连选中的“一手”与完整双选评价分开；本版仍测下一手。禁用题的位次字段表达首选/末选方，不能解释成已经有 5 名英雄选完。
- bans 未提及表示未知。合法性只能对已知已选/禁用检查。缺失 ban、构筑、补丁是适用边界，不应惩罚模型没有猜中隐藏信息。

## 每次运行保留

`run_id, case_id, skill_hash, knowledge_manifest_hash, model, provider, model_settings, executed_at, scenario_patch_assumption, raw_output, tool_trace, candidate_pool, build_assumptions, usage_tokens, latency_ms, error`。

不同 skill 版本须使用相同输入和环境，保留失败运行。若温度/服务不确定性影响结果，按相同重复次数报告波动，不用单次幸运命中选择版本。没有实际调用就不能填写 token/延迟/得分。

## 评分卡：先合法与诚实，再看机制

| 指标 | 定义 | 报告方式 |
|---|---|---|
| 执行完成率 | 合法结构输出 / 计划运行数 | 超时、工具失败单列，分母不静默减少 |
| 已知合法率 | 首选未在已选与已知 ban 中，且名称有效 | 不宣称未知 ban 条件下完全合法；ban 题另计 |
| 历史 Top-1 / Top-3 一致率 | 首选 / 最多前三候选与作者 accepted 交集 | 条件答案单列；不命中但合理者待专家审，不直接算策略失败 |
| 逐题机制检查 | 每题 rubric 的 3 项，逐项 0/1/2/U | 0=错误/缺失，1=正确但未连接本局，2=正确且解释条件与结果，U=资料不足无法判；U 不按 0 处理 |
| 机制幻觉率 | 核查后的事实性机制断言中，明确错误或无依据的比例 | 给出分子分母；严格区分来源缺证与已证伪；统计整题重大错误率 |
| 剩余回应覆盖 | 需要预见后续选人的题，是否处理具体可用回应 | 末手不强加未知第六手；回应被 ban/已选则不算有效分析 |
| 条件稳健性 | 反事实改变后，是否按正确机制调整结论 | 反事实未经专家确认前仅作探索，不发布 gold 分数 |
| 集合内非劣解率 | 在已审订有限候选集合中，首选未被明确支配 | 同时报候选覆盖率、不可比率与专家分歧，详见下节 |

三个 rubric 检查点是维护者提出的评价维度，不应要求模型逐字复述。合理等价机制可以得分；机械重复术语不能得满分。不要以答案名单命中替代理由正确性，也不要为精确复述作者的夸张结论加分。

历史 Top-1 应给两种分母视角：所有计划开发题上的命中率（失败仍在分母）和成功输出中的条件命中率，同时给出失败数量。选人、禁用分开。当前只有 3 道 ban，其中 1 道仍隔离，不足以稳定估计禁用决策总体能力。

## 有限候选集的 Pareto 审查

每题先确定候选集 C：作者参考、被测模型首选与备选、专家补充的可行挑战者。禁止只放一个首选，使其自动非劣；禁止只把作者答案放入 C，再把作者一致性改名为 Pareto。

每个候选记录以下五维的定性证据和失败条件，不强行转成共同尺度：

- 目标职责兑现：金库访问/伤害、圈内时间、携宝安全、球权得分、星数/生存。
- 对手压力：可达性、击杀/控制窗口、资源交换；不是裸 counter 边数。
- 队友增益：谁使谁的能力兑现、重复职责及互相破坏地形的成本。
- 应对稳健性：当前资源、地图转变、对方剩余选人下仍能完成什么。
- 执行成本：构筑承诺、Super 启动、技能冷却、路线与操作要求。

专家逐对判断 `better / equivalent / worse / unknown`，附理由和知识证据；假设不同先拆情景。若 y 对 x 所有维度都是 better 或 equivalent，且至少一维 better，才记录 `y dominates x`。任一必要维度 unknown 或存在权衡即不可据此支配。不要将“治疗→存活→站圈”三个相关表述当三份独立收益。

`non_dominated_selection_rate = 已充分比较且首选未被支配的题数 / 已充分比较的题数`。同时报告 `comparison_coverage = 已充分比较题数 / 计划题数`。低覆盖率的高非劣率不能说明决策优异。对不同的玩家熟练度或构筑，可形成不同前沿；41 题 Bull 尤其需要保留该条件。

当前没有构建专家确认的候选两两支配矩阵，因此不发布这个指标的数值。

## 防止小题库把测评分数推高

56 题来自 19 条视频，且多个首选题高度相似。这一批已经全部进入本次分析，应定位为开发/回归集；不能再把其中若干题称为本轮开发完全未见的盲测集。

比较改动时至少按视频分组，再对跨视频相同地图/同类局面进行近重复聚类。例：Ring of Fire 首选 12/54，Dueling 首选 27，同机制但并非独立证明；Shooting Star 首选 4/30，Belle's Rock 首选 24/42 也需成组审视。报告单题与组级结果，避免把熟悉模板放大成泛化收益。分组留一可辅助消融，但不能恢复已经失去的“未见”属性。

新封存集应来自后续未见视频、专家独立设计或独立审核的真实局面。派生反事实沿用父题分组，不算新增独立专家真值；未经审订的预期只能用来发现可疑行为。

## 错误归因和改动准入

每次失败归入：`source_state_error / retrieval_miss / known_fact_not_applied / knowledge_gap / objective_conversion_error / response_horizon_error / temporal_label_mismatch / reasonable_alternative / execution_failure`。允许多个标签，但注明主因。

只有核源完成、看到真实轨迹并定位主因后，才决定改召回、知识实体、skill 决策规则或评测标签。一次做一个可解释改动，报告新增通过、保持、退化；用 token 和延迟的真实观测判断工程代价。不能把 56 个作者答案直接加入可检索知识来提高本题库分数。
