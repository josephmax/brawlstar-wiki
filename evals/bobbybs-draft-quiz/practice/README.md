## 抽题和交互契约（应用已本地实现）

知识层维护题库与测评；应用层持有进度、用户作答和 UI skill。seed + 明确版本的伪随机算法进行 Fisher–Yates 洗牌，按持久游标顺序取题，一轮不重；重置指令 `/bp-quiz-reset [seed]` 清空练习游标与当前未答题，同 seed 可重放序列。算法固定，不能让 LLM 提供随机数；同时保存题库版本，版本变化显式开始新序列。题目与选项顺序使用分开的序列。

每次只发一题，至少一项“对”、一项“合理，但是有改进空间”、一项“不太合理”；正确选项池超过 3 项时轮换，单卡仍为 3–5 项。选一次方案即评分，不要求找齐所有正确选项。双选题的一个选项为无序两人组合。待审/缺正确证据题不可抽。

前端从现有新手引导进入；服务端先持久化题卡，再以 AG-UI 状态事件下发公开题面/选项。答案、标签、解释在用户提交前不进入 SSE、工具轨迹、前端状态。作答以题卡实例 ID + option ID 回传，服务端校验并幂等保存，再下发三档评价、全部正确方案及具体解释。刷新/重连恢复同一道题；重复点击不跳题，旧题提交不可影响新题。进度不能存临时 outputs。
