# 采集与核源

## 采集边界

按作者频道、系列标题、播放列表或明确日期范围发现视频，记录实际检索终点。系列同名不去重，video ID 去重；题号从同片内原顺序生成稳定 `bobby-<video-id>-q<n>`。新增视频追加 ID，不因重排目录改变现有 ID。不同平台搬运不能无依据算新独立样本。

优先使用可用的字幕导出/API，浏览器补足可见证据。原始自动字幕保存标记、语言、来源链接、采集日期及字节哈希；无字幕时记录失败，不编造逐字稿。只有访问到的内容才纳入覆盖统计；删除、私密、未发现内容不声称已收齐。

## 实际视频帧

本次经验：YouTube 初始封面可能与 `currentTime` 不一致，播放器按钮也会短暂滞后。必须先实际播放解码，确认封面消失；通过播放器 UI 定位并暂停/逐帧，核对画面内容及实际媒体时间。保存截图时记录捕获时间而非只记请求的跳转参数。播放中的近似时间明确写“约”；逐帧读取也不能冒称独立听辨原声。

使用当前可用的浏览器工具，遵循其文档。不要复制上一会话的 tab ID、元素索引、运行时绑定、DOM 私有状态或硬编码等待。页面操作后检查当前状态。看不到上方敌方/禁用栏时，先修正滚动和画面范围，不能用底部答案头像冒充完整题面。

截图与头像资源可裁剪/放大用于识别，但保留完整原帧。检查视频是否恰好显示该英雄还是仍在逐个引入头像。字幕、作者内嵌文字、头像、原音、评论属于不同证据；评论只作线索，自动字幕和同片推断不升级为直接确认。

## 核验顺序与记录

1. 全片约束：全片 ban、模式规则或特殊假设。确认后显式列出受影响 case，避免漏改其中一题。
2. 每题局面：地图、模式、当前已选、ban、位次/选边、连选范围。空阵容须区分“尚未选”与“视频没给”。
3. 作者标签：接受的默认候选、偏好、条件答案、实际玩家选择分开；未听清或未显示则保持未知。
4. 身份校准：canonical 索引先验 + 原帧实体对照。Nita 与 Najia 可同时合法，不能全局替换；小 pin 与大头像风格不同，无法可靠匹配就保留未识别状态。
5. 更新记录：稳定 case ID、字段、before/after、证据类型、URL、实际秒数、截图路径/哈希、观察说明、遗留项。确认“原值没错”也记审计。

对已选人数推位次，要标 `inferred_from_visible_state`，不能伪装成显式顺序。4/5 连选中作者说“投掷 + 保镖”，应保存无序组合；只把 Sprout 写为唯一下一手会错罚交换顺序的合法方案。

## 停止与降级

已取得一个无冲突直接证据就停止重复核验同字段。遇到封面未解码、主体裁切、模糊头像先修正观测；遇到真实缺帧、不可读 pin、缺失原音或不开放来源，记录尝试和具体缺口，保留隔离或带明确 partial-bans 的开发用途。不要用模型推理填成 ground truth，也不必为已授权的只读核验重复询问用户。
